# Адмін-панель FREERIDE PROJECT

Маршрути: `/login` (вхід, створення акаунта, UID користувача), `/admin` (редактор і керування адміністраторами).

## Підключення Firebase

1. Створіть або оберіть Firebase-проєкт. Зареєструйте Web App.
2. Скопіюйте `.env.example` у `.env` та заповніть параметри з налаштувань Firebase Web App. Це публічні параметри клієнта; приватний ключ service account не потрібен і не повинен потрапляти у frontend.
3. Увімкніть Authentication → Sign-in method → Google та/або Email/Password. Для входу Google додайте домен сайту та `localhost` у Authorized domains. Якщо використовуєте тільки один провайдер, інший можна залишити вимкненим: інтерфейс покаже відповідне повідомлення.
4. Створіть Cloud Firestore у **Native mode**, базу `(default)`, та Firebase Storage. Використовуйте вимоги до тарифу, показані у вашій Firebase Console.
5. Опублікуйте правила доступу з `firebase/firestore.rules` та `firebase/storage.rules` у Firebase Console. Або використайте `firebase deploy --only firestore:rules,storage --project YOUR_PROJECT_ID` після входу в Firebase CLI. Коли Storage звертається до Firestore, погодьтеся надати доступ сервісу в консолі/CLI.
6. Перезапустіть Vite після зміни `.env`.

## Бекенд для призначення адміністраторів за email

Права й дані адміністраторів зберігаються у Firebase. Для пошуку користувача за email інтерфейс звертається до довіреного Firebase Admin API бекенду (`POST /api/admins`).

Якщо frontend і backend — окремі проєкти Vercel, у **frontend → Settings → Environment Variables** додайте `VITE_API_BASE_URL=https://YOUR_BACKEND.vercel.app` для Production (і Preview, якщо потрібно). Значення — адреса бекенду, без `/api`. Виконайте новий деплой frontend: Vite вбудовує адресу API під час збірки. Локальний `.env` не змінює змінні вже розгорнутого сайту.

Помилка `POST https://freeride-theta.vercel.app/api/admins 405` означає, що запит потрапив на frontend замість бекенду. Перевірте `VITE_API_BASE_URL` та новий деплой. На бекенді мають бути налаштовані Firebase Admin і доступ до того самого Firebase-проєкту, що й у frontend.

### Помилка 503 на бекенді

Бекенд очікує `FIREBASE_SERVICE_ACCOUNT_JSON`: повний JSON service account із Firebase Console → Project settings → Service accounts → Generate new private key. Додайте його **тільки у backend → Vercel → Environment Variables**, як значення без зовнішніх одинарних лапок, для Production; потім виконайте Redeploy backend. `project_id` має відповідати Firebase-проєкту frontend. `FIREBASE_SERVICE_ACCOUNT_PATH` із локальним шляхом на комп’ютері не забезпечить доступ до файла на Vercel.

Не додавайте ключ до frontend, змінних `VITE_*`, репозиторію чи повідомлень. Якщо після налаштування 503 лишається, перевірте Vercel Runtime Logs: `Firebase admin init failed` означає проблему з ключем/JSON; `Grant administrator failed` — помилку доступу до Firestore або Firebase Auth. У frontend задано COOP `same-origin-allow-popups` для входу через Google; попередження браузера про вікно авторизації не визначає причину серверного 503.

## Перший власник

1. Увійдіть на `/login` через Google або створіть акаунт через email/пароль. Збережіть показаний UID.
2. У **Firebase Console → Firestore** створіть документ `owners/YOUR_UID` (поле `label` зі своїм ім’ям — за бажанням). Цей крок виконується тільки через довірену консоль: вебклієнт не може створювати власників.
3. Відкрийте `/admin`. Власник має доступ до редагування та розділу «Адміністратори».
4. Інші користувачі входять на `/login`, передають вам свій UID; ви додаєте UID і email у розділі «Адміністратори». Email є підписом, права прив’язані до незмінного Firebase UID. Відкликання доступу спрацьовує через правила Firestore/Storage, навіть якщо сторінка користувача ще відкрита.

## Контент

- Головна: заголовки, описи, кнопки, фон, три шари паралаксу, напрямки, про нас і відео.
- Події: заголовки, фон, відеопосилання.
- Звіти: створення/видалення, slug, дата, заголовок, опис, обкладинка, абзаци, галерея та підписи фото. Останній звіт/фото видалити не можна.
- Неопублікована чернетка зберігається в поточній вкладці браузера окремо для UID користувача; права доступу беруться тільки з Firebase.
- Зміни залишаються чернеткою до кнопки «Опублікувати зміни». Оновіть чернетку, якщо інший адміністратор опублікував нову версію. Транзакція з перевіркою revision не дозволяє непомітно перезаписати його зміни.
- Налаштування та тексти сторінок зберігаються в `site/main` (`storageVersion: 2`), кожен звіт — окремо в `reports/{slug}`. Фото, галерея та координати маршруту прив’язані до відповідного звіту; файли фото — у Firebase Storage. Публікація атомарна, із перевіркою revision; записуються лише змінені звіти. Обмеження у 30 звітів знято; за одну публікацію можна змінити/видалити до 450 документів звітів.
- Старий `site/main` із масивом звітів продовжує читатися. Наступна публікація автоматично переносить звіти в колекцію та використані локальні `/images/...` у Storage (повторювані адреси завантажуються один раз за публікацію). Перед нею обов’язково опублікуйте оновлені `firebase/firestore.rules`. Резервну копію старого документа можна зробити у Firebase Console.
- Сайт слухає публікації через Firestore; дані доступні всім відвідувачам і адміністраторам на різних пристроях. До першої публікації показується початковий контент. Поточний інтерфейс завантажує всі звіти; для дуже великого архіву наступний крок — пагінація списку та окреме завантаження сторінки звіту.
- Фото: JPEG/PNG/WebP/AVIF, до 10 МБ. Нові файли отримують унікальні адреси у Storage. Старі зображення не видаляються автоматично, щоб не зламати опубліковані посилання. Неприв’язані файли можна прибирати через Firebase Console після перевірки.
- Заміна основного hero-фото вимикає шари. Для 3D-паралаксу завантажте три суміщені фото однакового розміру, два передні — з прозорістю, та увімкніть перемикач.
- Навігація й службові підписи інтерфейсу залишаються у коді; основний редакційний контент редагується в адмінці.

## Перевірки

- `npm test` — перевірка формату контенту та URL.
- `npm run build` — TypeScript і production-збірка.
- `npm run test:admin` — повний сценарій входу, редагування тексту, завантаження фото, призначення/відкликання адміністратора та відображення змін на сайті. Потрібні Firebase CLI, Java 21 та Chrome (macOS; для іншої системи задайте `CHROME_BIN`). Тест сам запускає окремий Vite з тестовими параметрами та Chrome; реальний Firebase-проєкт не використовується.
- `npm run test:rules` — права гостей, звичайних користувачів, адміністратора та власника, відкликання ролі, revision та обмеження Storage. Потрібні Firebase CLI і Java 21. Використовується тільки локальний проєкт `demo-freeride`, без доступу до production.

Немає тестового входу чи клієнтського перемикача ролей. Без налаштованого Firebase `/admin` показує стан налаштування, а сайт працює з початковим контентом. Авторизацію, збереження й завантаження у вашому реальному Firebase потрібно перевірити після підключення та публікації правил.

Документація: [Google sign-in](https://firebase.google.com/docs/auth/web/google-signin), [Firestore Security Rules](https://firebase.google.com/docs/firestore/security/rules-conditions), [Storage Security Rules](https://firebase.google.com/docs/storage/security/rules-conditions).


## Пройдений маршрут для кожного звіту

У `/admin` → «Історії» → оберіть звіт → «Пройдений маршрут»:

- **Тестовий трек**: кнопка «Додати тестовий маршрут» додає схему біля Говерли, Драгобрата або Петроса. «Прибрати трек» видаляє її із чернетки. Початкові звіти вже містять ці демонстраційні маршрути; раніше опублікований контент залишається без змін. Це умовні точки, а не перевірені GPS-треки стежок. Карта Mapbox показує супутникові знімки, 3D-рельєф, лінію маршруту, початок і завершення. Доступні масштабування, нахил, обертання та повний екран. Потрібні інтернет і публічний токен Mapbox (налаштування нижче).
- **Google Earth**: додайте публічне посилання на проєкт, наприклад `https://earth.google.com/earth/d/15EABgg-l3xHSvMspAHvlEnrVTPMbXgdO?usp=sharing`. Перевірте доступ у приватному вікні браузера. 3D-проєкт відкривається в окремій вкладці: сторінка Google Earth надсилає `X-Frame-Options: SAMEORIGIN`, тому вставити її напряму в iframe цього сайту не можна.
- **Знімок маршруту**: необов’язково завантажте власний скриншот із Google Earth. Зберігайте зазначене на знімку авторство Google та постачальників даних. Це фото-прев’ю, а не інтерактивна карта.
- **Google My Maps**: для інтерактивної карти прямо у звіті створіть публічну карту з вашим маршрутом і вставте її посилання з параметром `mid`. Сайт сам формує дозволений iframe. Код HTML вставляти не потрібно. Ідентифікатор проєкту Earth не є ідентифікатором My Maps; потрібна окрема карта. [Офіційна інструкція My Maps](https://support.google.com/mymaps/answer/3109452?hl=en).
- Додайте опис і натисніть «Опублікувати зміни».

Без треку й посилань блок маршруту не показується. Локальний трек має пріоритет над My Maps; щоб показати My Maps або прев’ю Earth, приберіть тестовий трек. Посилання Earth залишається доступним і поруч із треком. Старий контент сумісний. На сторінці публічної My Maps можна використати супутниковий базовий шар; це не 3D-інтерфейс Google Earth. Для локальних треків уже використовується 3D-переглядач Mapbox; імпорт реальних треків KML/GPX/GeoJSON поки не реалізований.


## 3D-карта Mapbox

1. Створіть публічний токен у [Mapbox → Access tokens](https://account.mapbox.com/access-tokens/). Він має починатися з `pk.`. Для production задайте дозволені URL сайту; для розробки також дозвольте `http://localhost:5181` (або фактичний порт).
2. Додайте у `.env` рядок `VITE_MAPBOX_ACCESS_TOKEN=pk.ВАШ_ТОКЕН`. Секретні токени `sk.` не використовуйте у frontend.
3. Перезапустіть Vite. Для розгорнутого сайту задайте цю змінну в середовищі збірки та виконайте нову збірку.

Використовуються `satellite-streets-v12` і джерело висот `mapbox-terrain-dem-v1`: рельєф об’ємний, з підсиленням висоти 1.4 та початковим нахилом камери 60°. Лінія треку накладається на рельєф. Правою кнопкою миші або двома пальцями можна обертати й нахиляти карту; компас повертає орієнтацію на північ.

Без токена показується стан «3D-карта ще не підключена», треки залишаються збереженими. Недійсний токен, відсутність WebGL або помилка мережі показують повідомлення замість порожнього блоку. Не підміняємо карту двовимірною.

Перевірте завантаження супутникових знімків і рельєфу після додавання власного токена. `npm run test:admin` без токена перевіряє стан підключення та збереження треків; з `VITE_MAPBOX_ACCESS_TOKEN` також перевіряє завантаження карти й кінцеві позначки (потрібен Chrome із WebGL). Використання сервісу обліковується у вашому акаунті Mapbox: [тарифи](https://www.mapbox.com/pricing). [Офіційний приклад 3D terrain](https://docs.mapbox.com/mapbox-gl-js/example/add-terrain/).


## Відео у вікні сайту

У `/admin` → «Посилання» вставте URL конкретного відео YouTube (`https://www.youtube.com/watch?v=…`, `https://youtu.be/…`, Shorts або Live). За бажанням задайте окреме посилання на канал (`https://www.youtube.com/@…` або `/channel/…`) та опублікуйте зміни. Канал зберігається у `texts["video.channelUrl"]`; правила Firestore змінювати не потрібно.

Кнопки відео на головній, у подіях та звітах відкривають модальний YouTube-плеєр із керуванням і повним екраном. Плеєр завантажується тільки після натискання; закриття кнопкою, Escape або кліком поза вікном зупиняє відео. Унизу є перехід до відео та налаштованого каналу YouTube.

Початкове посилання на пошук YouTube не є відео і не вбудовується: замініть його адресою власного ролика. Якщо власник відео заборонив вбудовування або ролик недоступний, відкрийте його на YouTube. Автоматичний запуск після відкриття запитується у плеєра; браузер може вимагати додаткового натискання Play.


### Оформлення плеєра

YouTube-плеєр має власне оформлення: кругла кнопка Play, помаранчева шкала прогресу на всю ширину та темна нижня панель із назвою ролика, центральним керуванням, гучністю, швидкістю й повним екраном. Вигляд адаптовано за [референсом Varo](https://codepen.io/Varo/pen/vLdvMK) до кольорів FREERIDE. Для керування використовується Plyr та YouTube API; іконки зберігаються локально. На телефоні панель має два рядки: назва ролика й кнопки керування; звук перемикається кнопкою, повзунок часу залишається. Відео та канал налаштовуються в розділі «Посилання», як і раніше.
